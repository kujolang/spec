# Spec Release Artifact Policy

## Purpose

This document defines the required artifacts and provenance signals for every tagged Spec release.

## Required Artifacts

For each release version `X.Y.Z`, the release process must produce:

- `dist/kujo-spec-vX.Y.Z.tar.gz`
- `dist/kujo-spec-vX.Y.Z.sha256`
- `dist/kujo-spec-vX.Y.Z.provenance.json`

All three artifacts are generated by `scripts/release.sh`.

## Artifact Generation Rules

1. Build archive from repository state at `HEAD` using `git archive`.
2. Prefix archive contents with `kujo-spec-X.Y.Z/`.
3. Compute SHA-256 digest for the archive.
4. Write checksum file using the archive filename.
5. Emit provenance JSON containing:
   - `version`
   - `tag`
   - `commit`
   - `archive`
   - `sha256`
   - `generated_at` (UTC RFC3339)
   - `generator` (`scripts/release.sh`)

## Verification Rules

Before publication, verify:

- Release quality gates pass.
- Archive digest matches `dist/kujo-spec-vX.Y.Z.sha256`.
- Provenance `commit` equals the tagged commit.
- Published GitHub Release assets match local `dist/` files byte-for-byte.

## Dry-Run Behavior

`bash scripts/release.sh X.Y.Z --dry-run` must execute the same quality gates and artifact generation logic, but without creating commits, tags, or pushes.

## Distribution Policy

- GitHub Release assets are the canonical distribution channel.
- Homebrew formula remains `head` until a release tarball URL + verified SHA-256 are published.
- Any downstream packaging must use the published checksum and provenance metadata.
